## Sprint 7 · Nov 2 – Nov 8, 2026

### What shipped

#### fieldwire_client_ucsh
32 done · 264 points · 28 pull requests merged (roney4719)

The desktop app went out in 22 releases this week, v3.0.218 to v3.0.239.

- **Set up runs on the server.** Set up now runs on the access service like updates, so it keeps going with the app closed, resumes after a redeploy and can be retried, with attributes last so doors and checklists are usable early. It re-checks at 5 and 30 minutes only. ([#1078](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1078), [#1098](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1098))
- **Automatic door pinning for the dev role.** A door model trained on the company's own plans finds each sheet's doors and pins the sure ones, sending the rest to a confirm list. Everyone else keeps today's pin review. ([#1034](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1034))
- **Screens stay as you left them.** The last six screens stay open, so coming back keeps the open door, a typed note, zoom, scroll and filters, and the title bar shows a clickable path back. Pop-outs open from what the main window already loaded. ([#893](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/893))
- **Pop-outs beside the main window.** Windows now shrink enough to sit side by side, and every row and card has a pop-out button. A door opens as a full page with a back button, and export, PDF report and mirrors are toolbar buttons. ([#879](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/879), [#922](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/922))
- **History calendar.** History gained a calendar view beside its list, so PMs and QA/QC can see how a project moved. An opening register, a plans list, a timeline and a dashboard came with it and were taken out again within the week. ([#934](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/934))
- **Fewer views.** A project now has one doors view, history keeps its list and calendar, and plans is back to its card grid, marking plans that have pins. A door's plan opens beside the door. ([#994](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/994))
- **Bigger ways back.** The faint links back, which non-technical staff missed, are now one big labelled button, the new badge on pinned projects is gone, and content moves in instead of snapping. ([#1022](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1022))
- **Deficiencies panel removed.** Everything added to show deficiencies on Ontario doors came out, since it only renamed things and nobody asked for it; related tasks stays. ([#1021](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1021))
- **Mirror projects for contractors.** Contractors can be given a mirror instead of the real project: a copy kept in sync one way, with a chooser for what it copies. ([#738](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/738))
- **Changes credited to the person.** Records made through the app now show the signed-in person in Fieldwire instead of the shared UCSH API account, and updates are credited to whoever started them. ([#751](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/751))
- **Less reliance on the shared login.** Locations and categories made in the app now show who made them. Writes Fieldwire credits to no one, such as deletes, still need the shared login, so the app adds it to a project before its first write. ([#909](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/909))
- **Sign in inside the app.** Signing in now happens in the app window with an emailed code, for ucsh.com addresses only, and every sign-in, renewal and sign-out shows in the service log. ([#798](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/798), [#580](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/580))
- **Ready for Fieldwire's December 1 cut-off.** The app moved off the API version Fieldwire is retiring to its newest, 2026-10-06, and tests now fail any write Fieldwire's published schemas don't document. ([#987](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/987))
- **Ontario takes .mdb schedules.** Ontario set up and update now take an Avaware .mdb as well as its XML export, and read both the same. ([#986](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/986))
- **Duplicate lines caught before apply.** The review page now lists duplicate checklist lines before apply, instead of an update stopping partway on them, and a duplicate door found mid-run pauses and asks. A "not a door" answer no longer fails with a database error. ([#732](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/732), [#937](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/937))
- **BC updates change door attributes.** BC updates now take the openings file next to the APM file, so changed door fields are edited in place, and a door that only lost its hardware rows is no longer marked deleted. ([#766](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/766))
- **Updates stay green.** An update could read needs attention about 3 hours after going green, because its schedule files were deleted before its re-checks. Files now stay until every re-check is done. ([#1081](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1081))
- **Verify spares the request budget.** Verify read every new line one at a time, 10,833 reads on one job, using up the request budget so another job's writes were refused. It now reads by id only what its full read lacks. ([#1094](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1094))
- **Update fixes.** A service update no longer crashes when a door's attribute value changes, and a job that stops mid-apply no longer loses the delete marks on a removed door's lines. ([#1091](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1091), [#1100](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1100))
- **Activity panel.** The activity panel now shows the step a long job is on, such as "Step 4 of 5: Setting attributes, 3,200 of 7,746", and stays in front of the automations drawers. ([#1096](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1096), [#935](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/935))
- **Faster, smoother plans.** A plan now shows before its pins, loads in small 512 px tiles and stops re-measuring pins on every frame. The hover photo card on pins went, so a pin now opens its door on click. ([#657](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/657))
- **Updating the app.** The installer now closes the running app and its local service itself, and restart to update no longer ends its own installer. The reopened window keeps drawing when Windows thinks it is covered, and a startup log of where clicks go found the invisible layer below. ([#951](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/951), [#831](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/831))
- **No invisible layer blocking clicks.** Closing a menu or filter list could leave an invisible layer that blocked every click until a restart; closed menus, dialogs and drawers now let clicks through. Opening plans no longer blanks the window, and a failing screen shows an error page instead. ([#1009](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1009), [#981](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/981), [#975](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/975))

Closed without shipping: pin review's floorplan question ([#1120](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1120)), kept until automatic pinning replaces today's review; room fields on doors an update adds ([#1102](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1102)), not needed; set up stopping on a dropped connection ([#1073](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1073)) and the small home link ([#952](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/952)), both duplicates; moving the desktop check off Windows ([#919](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/919)); floorplan picking in pin review ([#669](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/669)), which automatic mode does without; sideways door tags ([#413](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/413)); undoing an update from its write log ([#390](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/390)); a vision model for pin review ([#386](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/386)), replaced by the trained door model; and driving the workflows conversationally ([#220](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/220)).

#### uc-nexus
7 done · 89 points · 9 pull requests merged (Xilous)

- **Shipping requests draw on the stock pool.** A shipping request can now take what its schedule's inventory lacks straight from the stock pool, with no separate stock request first; nothing moves until the warehouse and shipping managers both approve. ([#2177](https://github.com/Upper-Canada-Specialty-Hardware/uc-nexus/issues/2177))
- **Receiving no longer waits on GP.** Approving a count now books the hardware at once, so put-away, the shop and shipping carry on; registering it against the PO in GP is a second approval, any time after. ([#2210](https://github.com/Upper-Canada-Specialty-Hardware/uc-nexus/issues/2210))
- **Nexus on phones and tablets.** Nexus now works in a phone or tablet browser, and the warehouse can photograph a packing slip straight into a receive count, several pages making one document. ([#2242](https://github.com/Upper-Canada-Specialty-Hardware/uc-nexus/issues/2242))
- **Avaware schedules import.** Hardware schedules exported from Avaware now import through the same wizard as Titan files, and a PO draft no longer refuses a quantity past what its openings need. ([#2197](https://github.com/Upper-Canada-Specialty-Hardware/uc-nexus/issues/2197))
- **Specialties projects.** A project can now be flagged as a specialties project, only procurement, receiving and sending to the client: it never has a schedule and its inventory is its own, so it can ship what it holds. Projects with no schedule now say so before anyone fills a cart, and the inventory terms read the same on every screen. ([#2271](https://github.com/Upper-Canada-Specialty-Hardware/uc-nexus/issues/2271), [#2266](https://github.com/Upper-Canada-Specialty-Hardware/uc-nexus/issues/2266))
- **User guides.** Two ways of making step-by-step user guides were tried on one shipping request, and the owner chose guides written from what the app does, with their own screenshots, over Scribe recordings. ([#2192](https://github.com/Upper-Canada-Specialty-Hardware/uc-nexus/issues/2192))

Closed without shipping: shipping from a job with no schedule ([#2258](https://github.com/Upper-Canada-Specialty-Hardware/uc-nexus/issues/2258)), since the product owner ruled that a shipping request needs one.
