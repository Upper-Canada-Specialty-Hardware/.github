### What shipped

#### fieldwire_client_ucsh
39 done · 312 points · 41 pull requests merged (Xilous, roney4719) · 20 releases, v3.0.285 to v3.0.304

- **Jobs run as fast as Fieldwire allows.** Jobs now batch a door's checklist lines, run streams side by side and pace themselves from Fieldwire's own counts instead of our own cap, leaving room for people in the app. A mirror of a 680-door project took about 2 h 40 min where about 1 h is possible. ([#1381](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1381))
- **Project settings covers the whole setup.** Settings is now a dashboard with the managers once found only in Fieldwire's web app: project information, door fields, checklists, locations, report templates, and color and logo, with drag and drop to reorder. ([#531](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/531))
- **Regions show the right projects.** Switching between Ontario and BC now shows the new account's projects everywhere, not the list read at launch, and anyone can pick either region instead of it being tied to a sign-in role. ([#1406](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1406), [#1525](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1525))
- **BC sums repeated hardware lines.** A product listed twice on a door now lands as one line with the quantities added, as in Ontario, instead of keeping only the first. The door's hardware table gains shortcode, category, model and finish columns. ([#1437](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1437))
- **The door page fits on one screen.** Details, plan, related tasks, checklist, photos, attributes and comments sit in three zones, with fields edited in place, the full checklist text with who created each line, and a mini map that opens the plan on the door's pin. ([#1486](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1486))
- **Door page fixes.** List fields show their choice by name instead of an id, and every field the project shows appears, empty ones included, so it can be filled in. ([#1477](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1477), [#1632](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1632))
- **Sign-in with an emailed code from our own service.** People sign in with their company email and a 6-digit code from the access service, if the address belongs to a Fieldwire user in the Ontario or BC account, and Clerk is gone. ucaccess.com staff can sign in too, and sign-up errors were fixed. ([#1530](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1530), [#1454](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1454), [#1290](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1290))
- **A usable activity panel.** Activity is a top-bar button that opens almost full screen, with every run on the account and each step's count, time left and log. A waiting run says why, a quiet one warns it may be stuck, and a message appears when your run ends. ([#1610](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1610))
- **Failed runs stop and say why.** A run whose openings are all refused now stops with the reasons instead of going green, finished runs stay on the panel, and schedule files are checked first. Two other failed initialize runs were traced to Fieldwire validation rules and fixed. ([#1545](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1545), [#1555](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1555))
- **Writes follow each person's Fieldwire role.** Changes made through the app follow the person's own role on the project, and nobody is made an admin by the app. This also closes the work to stop everyone working as one shared Fieldwire session. ([#768](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/768), [#438](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/438))
- **Door finding for automatic pinning.** The door finder moved to the new model workspace, the access service reads room outlines, and pin review names a door with no number after the room it opens into. ([#1156](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1156))
- **Updates install in place.** Restart to update no longer runs the old uninstaller, which froze the 3.0.265 install twice at about 40%. Closing the app installs a waiting update, the version shows in the account menu, and a developer can push a version to everyone. ([#1356](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1356))
- **Updates download only what changed.** The backend ships as a folder, so an update swaps only the changed files, with the full installer as the fallback. A Check for updates button in the top bar asks for the newest version on demand. ([#1464](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1464), [#1581](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1581))
- **UCA electrified openings on Ontario projects.** UCA, the Ontario electrified division, now runs Titan initialize project and update on its own projects, with an Electrified Opening task per opening and a related ADO task where one is needed. ([#1412](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1412))
- **UCA runs ask for their categories.** Each UCA run asks which categories get the electrified openings and the ADO tasks, instead of using fixed names. ([#1513](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1513))
- **Open-source license notices.** The installer carries the license text of every open-source part it bundles, opened from the account menu, and dropping an unused video library shrank the backend from 150.6 MB to 138.2 MB. ([#1128](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1128))
- **Door dates and time zones.** Door start and end dates can be seen and edited on the door page and set in bulk. Project settings show each project's own Fieldwire time zone, and dates and history follow it. ([#1614](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1614), [#1637](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1637))
- **Set up stops writing unused room fields.** Ontario and BC set up no longer write Location1, ToFrom and Location2, which nothing read; on a 680-door project they were 2,040 of 7,746 attribute writes, 26%. ([#1109](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1109))
- **Mirror options change on a running mirror.** Turning an option off stops syncing it and deletes nothing; turning one on copies it in full. Form templates now sync too. ([#1357](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1357))
- **A new mirror copies right away.** A new mirror copies everything right after setup instead of waiting for the next office-hours sync, which once left one empty for about 90 minutes, and retries never make a second copy. ([#1405](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1405))
- **Official names for the sidebar automations.** UCSH Automations now read Initialize Project, Update Hardware Schedule, Task Pinning Tool and Set Task Location Tiers. Ontario gets back BC's related tasks by opening step, and a back-to-home button sits by the project name. ([#1418](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1418), [#1601](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1601), [#1419](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1419))
- **Set up shows what it will add.** Ontario set up previews the doors and checklist items it will add before any write, so adding a schedule partway through a job brings no surprise doors. ([#1461](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1461))
- **Releases publish to GitHub, after the server.** Each desktop version is now a GitHub release of this repository, with its changed patch files, and the releases site redirects to it. A release also waits for the server deploy of the same commit. ([#1570](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1570), [#1578](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1578))
- **Faster opening.** A plan's pins arrive with the plan, and the launch preload's disk copy opens on every launch, so a relaunch no longer reads every project again. ([#1364](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1364), [#1339](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/1339))
- **Tag every task related to a list of doors.** Select by list can select the tasks related to a pasted list of doors, so a tag or status applies to all of them. ([#655](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/655))
- **Upkeep.** CI drops four steps that did nothing, settings meet the org standard, and an npm install cut off part way now fails instead of passing. ([#961](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/961), [#962](https://github.com/Upper-Canada-Specialty-Hardware/fieldwire_client_ucsh/issues/962))
- **Releases.** The app also went out through the public fieldwire_client_ucsh_releases repository in 35 releases, v3.0.270 to v3.0.304.
